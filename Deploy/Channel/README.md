# Канал в контейнере

Канальный сервер (`Server.Login`) рядом с базой, с которой он работает. Контейнер входит
в сеть контейнера с базой, поэтому базы доступны по имени контейнера, а не через хост.

## Что нужно знать до запуска

**Порт берётся из базы, а не отсюда.** Канал ищет свою строку в `FNLParm.TblParmSvr`
по адресу и слушает порт из неё. Поэтому опубликованный порт обязан совпадать с `mTcpPort`
той строки, иначе клиент постучится не туда.

**Адрес регистрации и адрес прослушивания — разные вещи.** В `TblParmSvr` записан адрес
машины, и внутри контейнера его привязать нельзя. Поэтому `LoginSetting__ServerIp` остаётся
адресом строки в таблице, а `LoginSetting__BindIp` в контейнере равен `0.0.0.0`.

**DSN-файлов оригинала в образе нет.** Доступ к базам задаётся строками подключения
в `.env`, который не лежит в репозитории.

## Запуск

```bash
cp .env.example .env      # и заполнить реальными значениями
docker compose up -d --build
docker compose logs -f
```

Признак того, что всё сошлось, — в логе есть строка про найденную в `TblParmSvr` строку
канала и строка о том, что сервер стартовал на нужном порту.

## Игровой сервер

`Server.Game` в контейнер пока не заворачивался: у него та же развилка с адресом
регистрации, но отдельного параметра прослушивания у него ещё нет.
