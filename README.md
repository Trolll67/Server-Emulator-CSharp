# R2 Online — Server Emulator

Эмулятор серверной части MMORPG **R2 Online**, написанный на C# / .NET 10.

Исследовательский проект: попытка выяснить, насколько современный ИИ
способен разрабатывать и поддерживать эмулятор игрового сервера.

<sub>Неофициальный проект. Не связан с Webzen. Все права на игру принадлежат правообладателю.</sub>

</div>

## О проекте

Это эксперимент, а не продукт. Основная цель — не запустить игру, а
проверить на честной, достаточно сложной задаче, что ИИ умеет и чего не умеет:
реверс сетевого протокола, работа с бинарными пакетами, игровая логика,
состояние сотен одновременных сессий.

Эмулятор серверной части MMORPG — удачный полигон: здесь нет права на
«примерно правильно». Ошибка в смещении на один байт не падает сразу, а
тихо ломает протокол через сотню пакетов.

Проект развивается командой ИИ-агентов (планирование, разработка,
тестирование, ревью) — см. [`.claude/`](.claude).

## Сборка

Требуется **.NET SDK 10.0** или новее.

```bash
dotnet build Tested-Server.sln
```

Запуск серверов:

```bash
dotnet run --project Servers/Server.Login
```

```bash
dotnet run --project Servers/Server.Game
```

Адреса и порты задаются в `loginsettings.json` / `gamesettings.json`
соответствующих проектов.

### Доступ к базам

`Server.Login` берёт реквизиты **из DSN-файлов оригинального сервера** — тех же,
что читает он сам. Логин и пароль остаются в каталоге `Data` рядом с оригиналом
и в репозиторий не попадают: в конфигурации задаётся только путь.

Укажите каталог с `Account.dsn` и `Parm.dsn` — любым из способов:

```bash
FnlDatabase__DsnDirectory=/путь/к/CleanServer/Data dotnet run --project Servers/Server.Login
```

либо в нетрекаемом `appsettings.Local.json`:

```json
{ "FnlDatabase": { "DsnDirectory": "E:/R2/CleanServer/Data" } }
```

Имя базы — это имя DSN-файла: `Account` → `Account.dsn` → `FNLAccount`.
Из файла читаются `Address`/`SERVER`, `DATABASE`, `UID`, `PWD`; ключ `DRIVER`
игнорируется — оригинал ходит через ODBC, эмулятор через TDS.
Если каталог не задан или файла нет, сервер не стартует и называет конкретный
недостающий файл.

Когда DSN-файлов нет (например, в контейнере), доступ можно задать напрямую —
строкой подключения в `ConnectionStrings:Account` / `ConnectionStrings:Parm`;
она перекрывает DSN.

`Server.Game` пока остаётся на самодельных базах `R2Account`/`R2Game`/`R2Parm`
через EF Core — его перевод на оригинальную схему не сделан.

## Локальные материалы

Часть рабочих файлов намеренно **не хранится в репозитории** и перечислена
в `.gitignore` — это дампы трафика, выгрузки игровых данных и описания
структур, полученные при изучении оригинальных бинарных файлов. Они
производны от проприетарного ПО правообладателя и публикации не подлежат,
но остаются на машине разработчика как справочный материал:

```
Pc.h
Utilities/Dump/
Utilities/DumpAndParserPackets/{Dump5108,Monsters,NPCs}.json
```

На сборку они не влияют: это не компилируемые файлы, а единственные ссылки
на них в коде закомментированы (`Utilities/DumpAndParserPackets/Program.cs`).

## Статус

Экспериментальный. Стабильность, полнота протокола и совместимость с
оригинальным клиентом не гарантируются.

Решение собирается целиком, без ошибок.

| Часть | Состояние |
|---|---|
| `Server.Login` | работает на оригинальных `FNLAccount` / `FNLParm`: авторизация, список серверов, выбор сервера |
| `Server.Game` | работает на оригинальных `FNLGame` / `FNLParm` / `FNLAccount`: экран персонажей, создание и удаление, вход в мир, перемещение с валидацией; остальная игровая логика портируется |
| `Site.Balance` | выведен из solution: ссылается на отсутствующий проект `Databases/Database.Balance` |
